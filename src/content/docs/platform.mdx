## TL;DR

We use **Starlight** (Astro) for this tutorial. It gives us built-in i18n with fallback pages, a free offline search (Pagefind), MDX, and a clean default theme — without the build weight of Docusaurus or the Next.js lock-in of Fumadocs.

## Why a separate tutorial site

The tutorial is not a `README.md` and not a `docs/` folder inside the code repository. It lives in its own repository (`kwebhub/zkpool-tutorial`) for three reasons:

1. **Different audience.** The code repository is for developers who want to read the source. The tutorial is for learners who want a guided path.
2. **Different cadence.** Code changes on every commit. The tutorial changes when a stage is complete.
3. **Different deployment.** The tutorial is a static site. It can be deployed to GitHub Pages, Netlify, or Vercel for free — independently of the code repository.

## The candidates

Three documentation frameworks dominate the 2026 landscape:

| Framework | Built-in search | Built-in i18n | Build speed | JS by default |
|---|---|---|---|---|
| **Starlight** (Astro) | Pagefind, offline | Yes, with fallback | Fast | None |
| **Docusaurus** (React) | Algolia (needs account) | Yes | Slow | React runtime |
| **Fumadocs** (Next.js) | Yes | Partial | Medium | React runtime |

## Why Starlight

**Built-in i18n with fallback.** Starlight ships with locale-aware routing. Pages without a translation fall back to the default locale and show a notice — no broken links, no duplicate content. For a bilingual EN/RU tutorial, this is the deciding feature.

**Free, offline search.** Pagefind indexes the built site at build time. No Algolia account, no API keys, no per-request cost. Search works on GitHub Pages and offline.

**No client-side framework.** Starlight ships zero JavaScript by default. Pages load fast, Lighthouse scores stay high, and there is no React runtime to maintain alongside the tutorial content.

**MDX native.** Every page is `.mdx`. We can embed interactive components (checklists, tabs, callouts) without ejecting from the framework.

**Astro ecosystem.** If we later need a custom component — a live ZK proof checker, an interactive circuit visualizer — Astro supports React, Vue, Svelte, and Solid islands. We are not locked into one UI framework.

## Why not Docusaurus

Docusaurus is mature and has a larger plugin ecosystem. But:

- Build times grow with page count; a 100-page tutorial takes 5–20 seconds per rebuild.
- Search requires an Algolia DocSearch account (free for OSS, but an external dependency).
- i18n works, but the fallback semantics are weaker: missing pages 404 instead of falling back.
- It ships a React runtime, which is unnecessary weight for a content site.

## Why not Fumadocs

Fumadocs is visually modern and fast, but:

- It requires a Next.js App Router project. Our tutorial is not a Next.js app — adding one means maintaining a second stack (Next.js, React, TypeScript config) alongside Astro.
- Its i18n support is partial and less documented than Starlight's.
- The ecosystem is younger; fewer examples and third-party plugins.

## What we configure

In `astro.config.mjs`:

- `defaultLocale: 'en'` — English is the fallback.
- `locales: { en, ru }` — two locales, Russian is prefixed with `/ru/`.
- `sidebar` — grouped by stage, with `translations` for Russian labels.
- `social` — a single GitHub link to `kwebhub/zkpool-mesh`.

Content lives under `src/content/docs/en/` and `src/content/docs/ru/`. English pages are served at `/...`, Russian at `/ru/...`.

## Common errors

**`The collection "i18n" does not exist or is empty.`**
You enabled `locales` in the config but did not create `src/content/docs/en/` and `src/content/docs/ru/`. Starlight expects content in locale subdirectories once i18n is enabled.

**Pages 404 after switching language.**
The Russian page does not exist yet. Starlight's fallback only works when the locale is properly configured and the default locale's page exists. Create the `ru/` counterpart, or let the fallback show the English page with a notice.

**Search returns nothing.**
Pagefind indexes the built site, not the dev server. Run `pnpm build` and `pnpm preview` to test search.

## Reproduction

```bash
npm create astro@latest . -- --template starlight --no-install --no-git --typescript strict
# switch to pnpm
corepack enable && corepack prepare pnpm@latest --activate
pnpm install
pnpm approve-builds   # approve esbuild
pnpm astro telemetry disable
```

Then edit `astro.config.mjs` to add `defaultLocale` and `locales`.
